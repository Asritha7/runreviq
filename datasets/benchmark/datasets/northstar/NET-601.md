# Service discovery resolution

Fictional benchmark only. No real infrastructure or customer data.

## Situation

Fictional Harbor clients cannot resolve a downstream service name, while direct connectivity to a known healthy endpoint works. Record the queried hostname and resolver response code. A timeout and a nonexistent-name response require different investigation.

## Investigation

Compare DNS answers from a failing workload and a healthy workload. Inspect resolver configuration, search suffixes and the authoritative service record. Check whether a recent service rename left clients using an old hostname.

## Controlled response

Request the network owner to correct a verified record or resolver configuration through the approved change process. Avoid hardcoding endpoint addresses as a permanent workaround because endpoints may change. Preserve the original query and response for review.

## Verification

After correction, validate resolution from multiple workloads and account for record expiry before declaring recovery. If resolution succeeds but connections still fail, investigate routing and transport separately. Certificate renewal is outside this procedure.
