# Deployment readiness failure

Fictional benchmark only. No real infrastructure or customer data.

## Situation

A fictional Harbor rollout leaves new replicas unready while old replicas continue serving traffic. Record the rollout revision, probe result and last successful deployment. Distinguish process startup failure from an application that is running but cannot serve requests.

## Investigation

Inspect readiness probe responses, startup logs and dependency connectivity on one new replica. Compare configuration names and secret references with the previous revision without displaying secret values. Check whether the readiness endpoint incorrectly requires an optional downstream service.

## Controlled response

Pause rollout progression with the release owner and keep healthy old replicas serving traffic. Correct a verified configuration error through a reviewed deployment. Do not remove readiness checks merely to make the rollout appear healthy.

## Verification

Resume only after new replicas pass readiness and a small sample of requests succeeds. Use the rollback procedure if the release owner decides that the failure cannot be corrected within the incident window. Preserve logs from the failed revision.
